# 2026-10-23：FULL graph 接入验证

框架新增 `native compare --execution graph` 和 `recipes/ascend_graph.toml`，
沿用既有构建、campaign、服务 gate、比较、报告和搜索流程。默认仍为 eager。
Async CAM 的 graph 配置是 **Attention eager、FFN 显式 FULL**；两侧都使用
`FULL_DECODE_ONLY` 无法满足当前目标校验。该角色适配已固化在本仓库 E2E planner。

## 实际通过的验证

- iTASK 独立部署完整回归：**73 passed，无跳过**。本地 WSL 为 72 passed、
  1 skipped（本地 HTTP socket 权限）；配置测试已移除对相邻目标 checkout 的依赖。
- 真实 A3、1A+2F、H256/I512/E4、合成 W4A8 权重：冻结 campaign adapter 的
  correctness 和 benchmark 通过。参考由 layered eager 保存，事务阶段为 FFN FULL。
  每个 FFN 检查实际 capture/replay、稳定地址与禁止 Python eager 事务入口；
  correctness 保留元数据观察和边界 poisoning，benchmark 关闭这些诊断。
- 两个已有独立构建的 MegaMoe 版本执行 FULL 原生比较：共同 layered eager
  参考、两侧数值验证、两组 AB/BA、新建进程、JSON/Markdown 报告。两份构建的
  源码内容相同，仅验证框架的比较闭环，不作为优化候选或加速结论。
- 真实 DeepSeek V4 Flash W4A8、16 设备、DP2TP4/EP8、Async CAM MRV2：
  标准 vllm serve 启动、HTTP 就绪、smoke 请求通过，16 个实际进程加载身份
  和有界清理通过，campaign 服务 gate 通过。该环境不输出 FFN runner INFO
  模式日志；保留真实 FULL 配置、目标校验及原生 replay 证据，不虚构服务 capture 计数。
- 服务原始 status/shutdown_status 仍为 failed，包含 EngineDeadError 和
  `Async graph receive is pending; retain resources`。按既有冻结策略
  `require_clean_shutdown=false` 仅豁免关闭错误；推理、smoke、身份和清理通过。

`acccf801df79ae15c0828bcaed90b0b438ff66c2b0ad2a996fa38332b6ab957b`。

初次测试对旧构建硬编码两次 capture 的失败记录也保留；最终按是否存在 batch graph
检查 fixture 捕获次数，控制器拒绝缺失 capture/replay 或 eager 回退的证据。
